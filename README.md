# elevators_site

## Настройка переменных окружения

Для отправки заявок с формы проект использует серверный endpoint (`api/lead.js`) и отправляет письма напрямую по протоколу SMTP через библиотеку [`nodemailer`](https://nodemailer.com/), без привязки к стороннему провайдеру вроде Resend. Подойдёт SMTP любого почтового сервиса (Яндекс.Почта, Mail.ru, корпоративная почта, Gmail и т.д.). Все секреты должны храниться только на сервере в файле `.env` и не должны попадать в клиентский код.

### 1. Создайте файл `.env`

В корне проекта создайте файл `.env`. Проще всего взять за основу файл [.env.example](./.env.example) и скопировать его содержимое.

Пример:

```env
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=site@example.ru
SMTP_PASS=xxxxxxxxxxxxxxxx
LEAD_TO_EMAIL=manager@example.ru
LEAD_FROM_EMAIL=site@example.ru
LEAD_REPLY_TO_EMAIL=manager@example.ru
ALLOWED_ORIGIN=https://example.ru
```

### 2. Заполните каждую переменную

`SMTP_HOST`

- Адрес SMTP-сервера вашего почтового провайдера.
- Например, `smtp.yandex.ru` для Яндекс.Почты, `smtp.mail.ru` для Mail.ru.

`SMTP_PORT`

- Порт SMTP-сервера. Обычно `465` (SSL) или `587` (STARTTLS).

`SMTP_SECURE`

- `true`, если используется порт `465` (SSL/TLS с самого начала соединения).
- `false` для порта `587` (STARTTLS устанавливается после соединения).

`SMTP_USER` / `SMTP_PASS`

- Логин и пароль (или пароль приложения) от почтового ящика, от имени которого отправляются письма.
- Никогда не вставляйте эти значения в `index.html`, `script.js` или любой клиентский код.

`LEAD_TO_EMAIL`

- Адрес, на который будут приходить заявки с сайта.
- Обычно это рабочая почта компании или менеджера.
- Пример: `sales@liftkomplekt.ru`

`LEAD_FROM_EMAIL`

- Адрес отправителя, от имени которого сервер будет отправлять письма.
- Как правило, совпадает с `SMTP_USER` или является алиасом того же почтового ящика.
- Пример: `website@liftkomplekt.ru`

`LEAD_REPLY_TO_EMAIL`

- Необязательная переменная.
- Если указана, то при нажатии «Ответить» в почтовом клиенте ответ уйдёт на этот адрес.
- Если отдельный адрес для ответов не нужен, можно оставить тот же, что и в `LEAD_TO_EMAIL`, либо не использовать эту переменную совсем.

`ALLOWED_ORIGIN`

- Необязательная переменная для дополнительной защиты.
- Если указана, сервер будет принимать POST-запросы к `/api/lead` только с этим `Origin` (например, `https://example.ru`), что затрудняет использование вашего endpoint с чужих сайтов.
- Если переменная не задана, проверка Origin отключена (это ок для локальной разработки).

### 3. Пример для реального проекта

```env
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=noreply@liftkomplekt.ru
SMTP_PASS=пароль_приложения
LEAD_TO_EMAIL=info@liftkomplekt.ru
LEAD_FROM_EMAIL=noreply@liftkomplekt.ru
LEAD_REPLY_TO_EMAIL=info@liftkomplekt.ru
ALLOWED_ORIGIN=https://liftkomplekt.ru
```

### 4. Важные правила

- Файл `.env` должен находиться в корне проекта.
- Не коммитьте `.env` в git (он уже добавлен в `.gitignore`).
- `.env.example` можно хранить в репозитории, потому что в нём только шаблон без реальных секретов.
- Все переменные должны задаваться без кавычек, если в значении нет особой необходимости.
- После изменения `.env` обычно нужно перезапустить локальный сервер, чтобы он перечитал переменные окружения.

### 5. Что будет, если переменные не заданы

Если не указать `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`, `LEAD_TO_EMAIL` или `LEAD_FROM_EMAIL`, серверный endpoint не сможет отправить письмо. В этом случае форма вернёт пользователю сообщение на русском о временной недоступности сервиса, а подробности ошибки будут записаны только в серверный лог (не показываются пользователю).

### 6. Как проверить, что всё настроено правильно

1. Создайте `.env` по примеру из `.env.example`.
2. Укажите реальные `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`.
3. Укажите реальный почтовый адрес получателя в `LEAD_TO_EMAIL`.
4. Укажите адрес отправителя в `LEAD_FROM_EMAIL` (обычно совпадает с `SMTP_USER`).
5. Запустите проект: `npm run dev`.
6. Отправьте тестовую заявку через форму на `http://localhost:3000`.
7. Проверьте, что письмо пришло на адрес из `LEAD_TO_EMAIL`.

### 7. Частые ошибки

- Использован неверный логин/пароль от почтового ящика (`SMTP_USER`/`SMTP_PASS`).
- Неверно указан `SMTP_PORT`/`SMTP_SECURE` (например, `465` без `SMTP_SECURE=true`).
- Почтовый провайдер требует отдельный «пароль приложения» вместо обычного пароля от аккаунта (актуально для Яндекс.Почты, Gmail и т.д. при включённой двухфакторной аутентификации).
- `.env` создан не в корне проекта.
- После изменения `.env` сервер не был перезапущен.
- Секрет случайно вставлен в клиентский JavaScript вместо серверной конфигурации.

## Защита от злоупотреблений

Серверный endpoint `/api/lead` включает несколько механизмов защиты:

- **Rate limiting** — не более 5 заявок с одного IP-адреса за 10 минут. При превышении лимита возвращается ответ `429` с сообщением на русском языке.
- **Honeypot-поле** — скрытое поле `website` в форме, невидимое для обычных пользователей. Если оно заполнено, запрос считается ботом: сервер отвечает «успехом», но письмо не отправляет.
- **Проверка Origin** — если задана переменная `ALLOWED_ORIGIN`, запросы с других источников отклоняются.
- **Ограничение размера тела запроса** — локальный сервер (`server.js`) отклоняет запросы больше 10 КБ.
- **Строгая валидация полей** на сервере (длина, формат телефона) независимо от валидации на клиенте.
- Сообщения об ошибках, которые видит пользователь, никогда не содержат технических деталей провайдера почты или внутренних исключений — подробности пишутся только в серверный лог через `console.error`.
